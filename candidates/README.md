# Candidate Ledgers

One YAML ledger per upstream repository. Each ledger records which merged pull requests were looked at and the include / defer / exclude decision for each, so the intake is auditable and repeatable.

- The file name is the ledger slug. Pages generated from `candidates/<slug>.yaml` live in `sources/prs/<slug>/` and carry the id `pr-<slug>-<number>`.
- Ledgers: `llama-cpp.yaml` (GitHub, shaders), `ncnn.yaml` (GitHub, shaders), `mesa.yaml` (GitLab, driver source: RADV and ACO, ANV and the Intel compiler and device-info code, NVK and NAK, Turnip and ir3, Panvk and the Panfrost compiler, and the common cooperative-matrix lowering).
- The header is written by hand: `repo`, `keywords_used`, `license` (SPDX id, required before any upstream code is saved), `shader_path_markers`, `embedded_shader_path_markers` (optional; files of another language that hold GLSL text), `host_path_markers`, `architecture_code_markers` (optional; maps an identifier in the upstream code to an architecture node, see `scripts/pr_policy.py`). Further optional keys: `forge: gitlab` with `gitlab_api`, `license_path`, `architecture_path_markers`, and `scope_mode: driver` with `driver_path_markers` and `topic_patterns` for a repository of driver source, where a pull request is included when its title matches a topic pattern and it changes a driver path; and `artifact_exclude_path_markers` (path substring -> reason) for files whose own licence header is not the ledger's `license`, whose patches are never saved under `artifacts/`. The scripts fill in `searched_at`, `cutoff_date` and the counts.
- Rows are appended by `scripts/refresh_candidate_ledger.py`. The decision rules are in `scripts/pr_policy.py`: `include` when GLSL shader source was added or modified, `defer` when only backend host source changed, `exclude` otherwise.
- A refresh never changes an existing row. To override a decision, edit the row and add `decision_source: manual`; `--reclassify` leaves such rows alone. After widening a ledger's path markers or topic patterns, `--reclassify-excluded` recomputes only the rows that are excluded and not manual, so rows that already have a page keep the reason their page was written from.
- `scripts/fetch_pr_diff.py` saves the shader patches of `include` rows under `artifacts/prs/<slug>/`.
- `scripts/generate-pr-pages.py` turns `include` rows into source-pr pages. Rows it cannot turn into a valid page are listed in `data/pr-page-skipped.yaml`.

```bash
python3 scripts/refresh_candidate_ledger.py --cutoff YYYY-MM-DD [--repos <slug>]
python3 scripts/fetch_pr_diff.py [--repos <slug>]
python3 scripts/generate-pr-pages.py [--repos <slug>]
python3 scripts/validate.py && python3 scripts/verify_verbatim.py && python3 scripts/generate-indices.py
```

Both scripts call the GitHub API through the `gh` CLI and cache what they fetch under `.cache/pr-evidence/`, which git ignores.

## Manual review

A `defer` row changed backend host source but no shader. It is resolved by hand: set `decision` to `include` or `exclude`, give the `reason`, and add `decision_source: manual` and `reviewed_at`. In `llama-cpp.yaml` the 245 rows of this kind were reviewed on 2026-10-05 from their titles and changed paths: 65 were included (kernel selection, tile or subgroup tuning, shared-memory fit, device-specific kernel workarounds) and 180 excluded (memory, device setup, submission, build, logging, operator plumbing). In `ncnn.yaml` the 60 rows of this kind were reviewed the same way: 18 included, 42 excluded. In `mesa.yaml` 10 rows the rule had included were excluded by hand (stable-branch backports, the OpenGL driver, other vendors' drivers, a CI list, per-game profiles). The patches were not read for these reviews; correct a row if its diff says otherwise.

On 2026-10-10 the `mesa.yaml` header was widened from RADV / ACO to the other Vulkan drivers (driver paths under `src/intel/vulkan/`, `src/intel/compiler/`, `src/intel/dev/`, `src/nouveau/vulkan/`, `src/nouveau/compiler/`, `src/freedreno/vulkan/`, `src/freedreno/ir3/`, `src/panfrost/vulkan/`, `src/panfrost/compiler/`; topic patterns for subgroups, shared memory and SLM, DPAS / systolic / bfloat16, workgroups and compute shaders) and refreshed to that date with `--reclassify-excluded`. The 64 rows that already had a page were not recomputed. The rule then included 316 further rows; they were reviewed by hand from their titles and changed paths (the patches of six were read): 90 stay included, 213 were excluded (RADV / ACO rows matched only by the new topic patterns and not about cooperative matrices, subgroup size or compute shared memory: 75; general subgroup operations: 42; graphics, ray tracing, mesh / task, OpenGL, OpenCL, driver-internal shaders or old hardware: 37; per-application workarounds: 13; refactors, renames, tooling, limits and unrelated fixes: 46) and 13 RADV / ACO rows on compute shared memory, workgroup and subgroup-size handling were deferred (`rule: manual-deferred-outside-batch`) for a later decision on widening the AMD coverage. Two rows excluded on 2026-10-05 as another vendor's driver (13986, 26533) were included. A page generated before the widening keeps the architectures and paths derived then; `generate-pr-pages.py --force` would add the vendor nodes of the new path markers to it.
