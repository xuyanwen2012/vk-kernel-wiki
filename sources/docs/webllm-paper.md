# WebLLM: A High-Performance In-Browser LLM Inference Engine (arXiv 2412.15803v2; TVM / MLC-LLM compiled WebGPU kernels, not GLSL)

Language and backend of the source: WebGPU kernels (WGSL) generated by MLC-LLM and Apache TVM; not GLSL. Version quoted: arXiv:2412.15803v2 [cs.LG], 13 Apr 2026 (PDF of 7 pages). Text as extracted with `pdftotext -layout`; line breaks and hyphenation are those of the PDF.

## Excerpt: Section 2.3 "GPU acceleration with WebGPU via MLC-LLM", second paragraph (PDF page 4)

Locator: https://arxiv.org/pdf/2412.15803v2 (page 4, Section 2.3)

```text
    WebLLM resolves this by leveraging machine learning compilation libraries MLC-LLM
and Apache TVM to compile performant WebGPU kernels. MLC-LLM ingests any open-
source model’s implementation in Python, which can use techniques such as the aforemen-
tioned PagedAttention and FlashAttention, and compiles the model’s computation into
the backend of interest (in this case, WebGPU). Besides compiling to the specified target,
MLC-LLM provides both graph-level optimizations (e.g. kernel fusion) and operator-level
optimizations (e.g. GEMM tiling) to improve kernel performance.
```

## Excerpt: Section 3 "Evaluation", first paragraph (PDF page 4)

Locator: https://arxiv.org/pdf/2412.15803v2 (page 4, Section 3)

```text
   We evaluate WebLLM by comparing it against MLC-LLM on the same Apple MacBook
Pro M3 Max. WebLLM executes in the browser using JavaScript, WebAssembly, and
WebGPU, whereas MLC-LLM runs natively on the same hardware using a Python and
C++ stack with Metal kernels. Table 1 reports decoding throughput in tokens/s for 4-bit
quantized models. Across the tested models, WebLLM retains up to ∼80% of the decoding
throughput of MLC-LLM on the same device. These results indicate that browser-based
deployment can approach the performance of a native deployment while preserving the
accessibility and portability advantages of the web platform.
```
