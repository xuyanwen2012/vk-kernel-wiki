# vulkan : fix out-of-bounds access in argmax kernel

Locator: https://github.com/ggml-org/llama.cpp/pull/15342 (pull request description, complete)

<!-- upstream-excerpt-start -->
The Vulkan argmax kernel could access rows beyond the input tensor size.

- Added a check that the processed row is within bounds
- Avoid partial workgroup return before a `barrier()`. Not sure how Vulkan handles this, but I think in general, either all threads should stop on the barrier or none. Otherwise, it could be undefined behaviour?
