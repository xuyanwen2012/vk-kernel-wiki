# vulkan: add FA dequant for q4_1, q5_0, q5_1, iq4_nl

Locator: https://github.com/ggml-org/llama.cpp/pull/21029 (pull request description, complete)

<!-- upstream-excerpt-start -->
I noticed that q4_1, q5_0, q5_1, and iq4_nl KV cache types run about 3x slower than q4_0/q8_0 on my R9700 (Vulkan, gfx1201). Dug into it and found three things blocking them from the flash attention path:

1. No `dequantize4()` in `flash_attn_base.glsl` for these types
2. Shader generator wasn't compiling FA variants for them
3. `supports_op` gated them to coopmat2-only

The dequant math follows the existing patterns. q4_1 is q4_0 with an additive min. q5_0/q5_1 add a 5th bit from the qh field. iq4_nl uses the existing kvalues_iq4nl lookup table (shared memory init was already wired up via NEEDS_INIT_IQ_SHMEM).

After the fix, all four types match q4_0/q8_0 throughput (~99 tok/s on Qwen3.5-35B-A3B). Tested on AMD Radeon AI PRO R9700, Vulkan backend.

Note: I used Claude Code to help with the implementation. The shader math was derived from the existing standalone dequant shaders.
