# vulkan: add TQ1_0 support (mm, mat-vec, mat-vec-id, dequant, get_rows)

## Overview

Adds the TQ1_0 ternary type (1.6875 bpw, base-3 packing — format by @compilade, thanks for TQ1_0/TQ2_0!) to the Vulkan backend. This was one of the last "TODO: implement for all backends" holes for this type, so consider it closed on Vulkan now.

What's in here:
- `block_tq1_0` struct + dequant functions, scalar and coopmat2 both
- mul_mm support in `mul_mm_funcs.glsl`
- Two new shaders: `mul_mat_vec_tq1_0.comp`, `dequant_tq1_0.comp`
- Pipeline creation + op-support wiring in `ggml-vulkan.cpp`
- Enabled TQ1_0 in test-backend-ops type lists, and added some MUL_MAT_ID cases at real MoE decode shapes (n=1, 28/128/512 experts, k=2048/4096)

Why I bothered adding those specific shapes: turns out the mat-vec shaders get `a_offset` already in block units from `get_offsets()`. My first draft divided by QUANT_K again on top of that — which is fine at offset 0 (nothing to divide, basically), but during actual mul_mat_id decode it just quietly grabs the wrong expert. No crash, no error, just wrong output. The normal test matrix never has n<16 or offset≠0 so it sailed right past.
