# vulkan: sparse flash attention for quantized K/V

Locator: https://github.com/ggml-org/llama.cpp/pull/29639 (pull request description, first 1197 of 2817 characters)

<!-- upstream-excerpt-start -->
## Overview

Vulkan's sparse flash attention only activated when K and V were f16. So models that use sparse attention with a quantized cache (Qwen3.8-Flash-Next QSA, DeepSeek-style) ran dense attention over the whole context, even though only ~2k cells are actually kept. This PR turns it on for quantized K/V.

The scalar and coopmat1 paths already dequantize each gathered row through the sparse index, so the gate in `ggml-vulkan.cpp` just needs to let quantized K/V through. coopmat2 stays f16-only, because its gather callbacks read f16. `flash_attn.comp` had one real bug: the scalar MMQ K loads used raw column numbers, so they didn't follow the sparse index list. They now go through `fa_kv_index` like the other paths.

There is also a separate threshold for quantized K/V: 16x minimum context/kept ratio instead of 2x (f16 unchanged). Upstream's 2x regressed decode by 4% at 16k. A sweep over 20k/24k/28k/32k put the break-even between 12x and 16x, and 12x still lost 1.3% at 24k, so I went with 16x.
