# vulkan: Fix mismatch in TOPK_MOE unit test

Locator: https://github.com/ggml-org/llama.cpp/pull/17541 (pull request description, complete)

<!-- upstream-excerpt-start -->
We are currently seeing a mismatch in all TOPK_MOE unit tests on our upcoming platform. This is due to an implicit assumption in subgroup and workgroup mapping. For example the current topk_moe shader assumes that each subgroup lane is contiguous in the x dimension of a workgroup which [is not exactly guaranteed](https://docs.vulkan.org/refpages/latest/refpages/source/SubgroupLocalInvocationId.html) .
 - `There is no direct relationship between SubgroupLocalInvocationId and LocalInvocationId or LocalInvocationIndex`

On the failing platform we were observing a single subgroup getting mapped in a 2D workgroup ID. For subgroupID 0 we get gl_LocalInvocationID.x: 0-7 and gl_LocalInvocationID.y: 0-3, whereas on other platforms it was gl_LocalInvocationID.x: 0-31 and gl_LocalInvocationID.y: 0.

We've tested [4404be4](https://github.com/ggml-org/llama.cpp/pull/17541/commits/4404be40ea05e1eb0396c9fb17368a92aca0f12f) on Intel/NVIDIA/AMD GPU for Windows,  Intel/NVIDIA GPU for Linux and confirmed `test-backend-ops.exe -o TOPK_MOE` passes
