# vulkan: fix buffer_reference alignment in im2col shaders

Locator: https://github.com/ggml-org/llama.cpp/pull/28996 (pull request description, first 1200 of 1800 characters)

<!-- upstream-excerpt-start -->
## Overview

This PR fixes a Vulkan validation error (`VUID-RuntimeSpirv-PhysicalStorageBuffer64-06315`) reported under GPU-AV in two shaders: `im2col.comp` and `im2col_3d.comp`.

The cause is a missing `buffer_reference_align` on the output pointer. `D_ptr` is currently declared as `layout (buffer_reference) buffer D_ptr {D_TYPE d;};`, and without an explicit alignment glslang emits every write through it with `Aligned 16`. The shader advances the pointer by `D_SIZE`, which `vulkan-shaders-gen.cpp` (lines 1111-1112) sets to 4 for `float` and 2 for `float16_t`, so most write addresses aren't 16-byte aligned. The fix declares `buffer_reference_align = D_SIZE` so the declared alignment matches the actual stride.

Note on the 1-PR limit: Jeff asked for this PR on #28960 and cleared opening a second PR ("It's fine to open another PR."), which is why it's open while my other PR is still active.

Closes #28960
