# Fix bug in handling slice of array being passed cooperative matrix load/store functions and strengthen error checks.

Locator: https://github.com/KhronosGroup/glslang/pull/4007 (pull request description, complete)

<!-- upstream-excerpt-start -->
Handle cases which were previously not working like
```
layout(binding = 0) buffer block
{
    float16_t f16arr[256][256];
};

coopMatLoadTensorNV( mat, f16arr[ 1 ], 0, t )
```
Also error out invalid uses for second argument buf[] to these intrinsics
For ex

```
void main()
{
    float16_t f16arr[16];
    coopMatLoadTensorNV( mat, f16arr[ 1 ], 0, t )
}
```

Since spec states
_The "buf" arrays must be in either buffer storage or shared
    storage, and the array that is passed in can be sized or unsized._
<!-- upstream-excerpt-end -->
