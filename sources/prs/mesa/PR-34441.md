# ir3: Move load/store vectorization to finalize, vectorize shared memory

Locator: https://gitlab.freedesktop.org/mesa/mesa/-/merge_requests/34441 (merge request description, complete)

<!-- upstream-excerpt-start -->
I noticed when looking at a particularly bad compute dispatch in Path of Exile 2 that we weren't vectorizing shared memory loads or stores. Fixing that led down a rabbit hole, because it turns out that rusticl will call the driver's optimization function without the layout decided and so we have to do what other drivers do and call `nir_opt_load_store_vectorize` only once late in the pipeline. However it turns out that we really want this anyways, because if we call it before I/O is lowered it inserts casts that destroy our ability to get UBO ranges and therefore we weren't pushing vectorized UBO loads to constants.
