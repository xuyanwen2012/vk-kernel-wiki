# spirv, nir, ir3, turnip: Implement concurrent workgroup dispatch

Locator: https://gitlab.freedesktop.org/mesa/mesa/-/merge_requests/41562 (merge request description, first 1199 of 1524 characters)

<!-- upstream-excerpt-start -->
The current Vulkan and DX12 specifications provide no guarantees about whether workgroups in a compute dispatch are executed in a "fair" manner, i.e. they provide no forward progress guarantees, so that algorithms using atomics to implement spin-locks are impossible to write correctly. However, not to be deterred, the developers of PRAGMATA decided to make some assumptions anyway. The game implements a work-stealing scheduling algorithm in its culling pass, which relies on so-called "occupancy-based execution" fairness to avoid deadlock: each workgroup which has already taken a step, i.e. has already been dispatched, must eventually make another step. This is a very mild assumption, which most GPUs already satisfy.

However... it turns out that Adreno does not meet this assumption by default, unless a magic bit in `SP_CS_CNTL_0` is set to change the scheduling mode to round-robin. There is also a workaround required on some a6xx-a7xx GPUs. We probably don't want to set the bit on every shader, and we especially shouldn't enable the workaround for every compute shader.
