# intel/compiler: Delete brw_nir_apply_key, rework subgroup size handling

Locator: https://gitlab.freedesktop.org/mesa/mesa/-/merge_requests/42939 (merge request description, complete)

<!-- upstream-excerpt-start -->
This patch moves the single last remaining thing dealing with the program key out of brw_nir_apply_key and into the drivers.  At that point, the remainder of brw_nir_apply_key has everything to do with optimizing for subgroup sizes.  This reworks that a bit so that we optimize for known sizes early (say due to specified limits or known hardware dispatch widths) but defer the rest until a bit later.

My hope here is to make it possible for jay to run the majority of NIR passes prior to per-SIMD cloning, and then just optimize SIMD calculations after that point.  That way, if we need to compile multiple SIMD modes, we can share most of the cost of the NIR compile time across all of them.

Also I think this is just a cleanup.  Having the very first pass we call be tied to the SIMD size is a bit silly.
